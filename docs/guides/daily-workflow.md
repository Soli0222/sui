# 概要

登録を終えたあとに繰り返すのは三つだけである。

- 予定日を過ぎた支払いを確定する。
- 通帳の残高と突き合わせる。
- 立て替えた分を記録して、返ってきたら消し込む。

どれも自動では進まない。
予定額と実額は一致しないので、金額を見た人間が決める前提で作ってある。

# 確定キューを処理する

予定日を過ぎても確定していない予測イベントは、ダッシュボードの「確定キュー」に溜まる。
サイドバーの「ダッシュボード」に付く件数バッジがその数である。

一件ずつ、実際に落ちた金額と口座を確認して確定する。
金額が予定と違っていれば、その場で実額に直してから確定する。
複数件を選んで「選択した N 件を確定」でまとめて処理することもできる。

確定すると、口座残高の更新と取引の作成が同時に行われ、そのイベントは予測から消える。
一度確定したイベントを二重に確定することはできない（[予測イベント](../concepts/forecast-event.md)）。

落ちなかった支払いは確定しない。
予定そのものが消えたなら、元の予定収支やカード請求の側を直す。

# 残高を照合する

記録は少しずつずれる。
現金払いの入れ忘れ、手数料、身に覚えのない引き落とし。

「口座管理」の照合ボタンから、通帳の残高を入力する。
差分があれば `残高照合` という調整取引が当日付で作られ、口座の残高と最終照合日時が更新される。
一覧の「最終照合」列で、どの口座をしばらく見ていないかがわかる。

差分を消すのではなく取引として残すので、いつどれだけずれたかは後から追える。
照合の結果を過去に遡って反映することはしない（[残高照合と調整取引](../concepts/balance-reconciliation.md)）。

残高を直接編集しても差分は調整取引になるが、最終照合日時は更新されない。
通帳を見て突き合わせたときだけ照合を使う。

# 手動の取引を記録する

現金の入出金、口座間の振替、臨時の支出は「取引履歴」から記録する。
記録すると口座残高がその場で動き、過去の残高推移グラフにも反映される。

グラフは取引から逆算して描いている。
古い取引を後から追加すると、その日以降の履歴が引き直される。

# 割り勘を記録する

立て替えた支出は、まず通常の支出として記録する。
口座からは実際に出ているので、これで残高の側は正しい。

そのうえで「割り勘」に、誰がいくら負担するかを登録する。

- **メンバー**タブで相手を登録する。未回収の合計が人ごとに出る。
- **割り勘一覧**タブで立替を登録する。均等、比率、金額指定のいずれかで割る。端数は自分の負担に寄る。
- 返ってきたら**精算**タブで消し込む。振込で受け取ったなら、その振替取引に紐づける。現金や相殺なら日付を指定して記録する。

割り勘の金額は残高予測には入らない。
立替の支出も回収の入金も、既に実取引として残高に出ているからである（[割り勘と精算](../concepts/split-and-settlement.md)）。

精算が付いた割り勘は編集も削除もできない。
直すには先に精算を取り消す。

# 想定額を見直す

カードの想定額が実態と離れてくると、予測が甘くなるか厳しくなりすぎる。

「クレカ管理」のカード編集画面に「過去実績から提案」がある。
直近 6 か月の実績から想定額を出すので、そのまま採用してもよいし、参考値として見てもよい。

# バックアップを取る

「データ管理」から全データを JSON で書き出せる。
論理削除済みの行も含まれる。

インポートは差分ではなく全置換である。
取り込むと既存のデータはすべて置き換わる。
