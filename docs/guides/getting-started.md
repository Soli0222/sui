# 概要

空の状態でダッシュボードを開いても、線は引かれない。
予測は登録した内容から組み立てるので、先に材料を入れる。
順番には理由があり、後の登録が前の登録を参照する。

1. 口座
2. 固定収支
3. クレジットカード
4. ローン
5. サブスク台帳

サブスクだけは予測に影響しないので、最後でも最初でも構わない。

# 1. 口座を登録する

「口座管理」で、通帳やアプリに出ている残高をそのまま `残高` に入れる。

`オフセット` には、あるものとして数えたくない額を入れる。
生活防衛資金や、使い道の決まっている資金がここに当たる。
迷うなら 0 のままでよい。
一覧には「残高」と「可処分残高」が並び、その差がオフセットである。

外貨の口座は通貨コードを選ぶ。
換算レートは自動で取得するので入力しない（[複数通貨と JPY 換算](../concepts/multi-currency.md)）。

# 2. 固定収支を登録する

給与、家賃、通信費など、毎月または毎週の決まった収支を入れる。

- **口座**：どの口座が動くかを指定する。指定しないと合計残高だけが動き、口座別のグラフには出ない。
- **振替**：口座間の定期的な移動は種別を「振替」にして、出金元と入金先を指定する。
- **日付シフト**：引き落としが土日祝に当たったとき、前後どちらの営業日に寄せるかを選ぶ（[スケジュールと営業日シフト](../concepts/schedule-and-business-day.md)）。
- **開始日と終了日**：期限付きの支払いはここで区切る。

カード払いの定額サービスをここに入れると、カード請求と二重に数えてしまう。
サブスクは次の手順のカード請求に含めるか、台帳だけに登録する。

# 3. クレジットカードを登録する

カードごとに、引き落とし口座、締め日、想定額を入れる。

想定額は「毎月だいたいこれくらい使う」という額でよい。
請求が確定するまではこの額で予測し、確定したら実績額に切り替わる。
過去の実績が溜まってくると、カード編集画面から想定額の提案を取得できる。

実績額は「クレカ管理」から月ごとに登録する。
翌月以降の月は、実績が想定額を下回っていても想定額のほうを使う（[クレジットカード請求の仮定値と実績](../concepts/credit-card-billing.md)）。

# 4. ローンを登録する

返済総額、返済回数、開始日を入れる。
月々の返済額は入力しない。
残額を残回数で割った値を毎回計算する（[ローン返済の再計算](../concepts/loan-repayment.md)）。

支払い方法がクレジットカードのローンは、予測イベントを作らない。
カード請求額に含まれているためである。

# 5. サブスク台帳を登録する

金額、周期、支払い元を入れる。
月別の一覧と年間合計が出る。

台帳は残高予測には反映されない。
理由は [サブスク台帳](../concepts/subscription-ledger.md) にある。

# 確認する

ダッシュボードを開くと、合計残高から予測イベントを積み上げた線が引かれる。

- 上部の判定は、予測期間中に残高がマイナスへ沈むかどうかを示す。
- 「可処分残高で表示」を切ると、オフセットを引かない実残高の線に変わる。
- 「口座別の水位」で、どの口座が危ないかを見る。赤は実残高がマイナスになる予測、黄はオフセットに食い込む予測である。

日々の使い方は [日々の運用](./daily-workflow.md) にある。

# 認証を設定する

自分以外がアクセスできる場所に置くなら、OIDC を設定する。
`SUI_OIDC_ISSUER`、`SUI_OIDC_CLIENT_ID`、`SUI_OIDC_REDIRECT_URI` と、許可する `sub` かメールアドレスのいずれかが要る。
一つでも欠けると未構成として扱われ、ログインできない（[設定と環境変数](../operations/configuration.md)）。

`SUI_OIDC_REDIRECT_URI` は `https://sui.example.com/api/auth/callback` のような絶対 URL で書く。
パスの `/api/auth/callback` は固定で、前に付けるのは公開している URL のスキームとホストである。
同じ値を IdP 側にもリダイレクト URI として登録する。

`SUI_OIDC_CLIENT_SECRET` は confidential client のときだけ設定する。
シークレットを持たない public client では PKCE だけで完結するため、設定しなくてよい。

MCP クライアントから使う場合は、「設定」で API トークンを発行する。
読み取り専用のトークンも発行できる。
