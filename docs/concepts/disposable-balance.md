# 概要

通帳に 50 万円ある。
だからといって 50 万円を使えるわけではない。
その中には翌月の家賃も、引き落とし待ちのカード代も、動かすつもりのない生活防衛資金も混ざっている。
実残高をそのまま眺めていると、この差が見えない。

sui は口座に二つの数値を持たせて、この差を明示する。
`balance` が通帳に載っている実残高、`balanceOffset` が「あるものとして数えない額」である。
**可処分残高**は `balance - balanceOffset` で、ダッシュボードの合計残高も口座別の残高推移も、既定ではこちらを基準に計算する。

オフセットの意味づけはアプリ側では決めない。
生活防衛資金として固定しておく人もいれば、当座の心理的な下駄として使う人もいる。
アプリが保証するのは、その額を差し引いた系列と差し引かない系列を、いつでも切り替えて見られることだけである。

# 規則

- 可処分残高：`balance - balanceOffset`。負になっても計算上は許容する。
- `applyOffset=true`（既定）：合計残高、口座別 `currentBalance`、予測の各時点残高、過去の残高推移を、すべて可処分残高ベースで返す。
- `applyOffset=false`：同じ系列を実残高ベースで返す。オフセットの効き方を確かめたいときに使う。
- 複数通貨の口座がある場合、合計は各口座を JPY 換算してから足し合わせる。詳細は [複数通貨と JPY 換算](./multi-currency.md) を参照。

`applyOffset` を受け取るのは `GET /api/dashboard`、`GET /api/dashboard/events`、`GET /api/transactions/balance-history` の三つである。

# 口座ごとの警告レベル

口座別の予測には `warningLevel` が付く。
判定に使う残高は二系統あり、オフセットを引いた残高と、引かない実残高を並行して進める。

- `red`：予測期間中に実残高が一度でもマイナスになる。引き落としが実際に落ちない可能性がある状態で、オフセットの設定とは無関係に危険である。
- `yellow`：実残高はマイナスにならないが、可処分残高がマイナスになる。手を付けないと決めた額に食い込んでいる。
- `none`：どちらもマイナスにならない。

`red` と `yellow` を分けているのは、対処の緊急度が違うからである。
`yellow` は予算の話であり、`red` は決済が失敗する話である。

# 例

```
balance        = 500000
balanceOffset  = 200000
可処分残高      = 300000
```

この口座から 35 万円のカード代が引き落とされる予測があると、可処分残高は -50000 まで沈み、実残高は 150000 で踏みとどまる。
このとき `warningLevel` は `yellow` になる。
