# 概要

ふるさと納税の寄付は、支出として実際に口座残高から引かれるが、このアプリでは「寄付台帳」として独立させて記録する。

額面そのものを将来の住民税控除や所得税控除の計算に使う可能性があるため、確定申告の入力補助として参照できる形で残す。

# 独立台帳である理由

- ふるさと納税の寄付は支出として口座残高に既に反映される。台帳を予測パイプラインに組み込むと、同じ支出を再び数えることになる。
- ふるさと納税の控除計算は、残高予測とは別の関心事である。
- ふるさと納税の寄付額は特定の自治体に対するものであり、残高予測の予算項目として区別して管理したい。

# 記録項目

| 項目 | 意味 |
|------|------|
| `recipient` | 寄付先（自治体を想定するが自由入力）。前後の空白は詰めて保存 |
| `amount` | 寄付額。JPY の最小単位の整数。1 以上、int32 の範囲 |
| `memo` | 任意のメモ。最大 200 文字 |
| `donatedOn` | 寄付日。年フィルタと集計はこの暦年で行う |

金額は通貨の最小単位の整数で保持し、int32 の範囲を超える値は拒否する。

# 集計

年フィルタは `donatedOn` の暦年で行う。1 月 1 日から 12 月 31 日までの `amount` を合計して表示する。

# 残高・予測との関係

寄付台帳は残高予測や口座残高に影響しない。実際の支出は取引として記録済みである前提であり、寄付台帳はあくまでメタデータとして保持する。

# 控除シミュレーション

シミュレーションは、対象年の給与台帳・寄付台帳と年単位の手入力値から、ふるさと納税の上限額と控除内訳の目安を計算する。確定申告機能ではなく、正確な税額を保証するものでもない。

手入力する値は、未支給賞与の見込み額面、給与以外の所得金額、社会保険料控除・基礎控除以外の所得控除である。年をキーに一件だけ保存し、更新時は上書きする。

## 給与と社会保険料の見込み

給与収入見込み `R` は、対象年の給与・賞与の実績額面に、最新の月給を残月数だけ外挿した額と未支給賞与見込みを加える。賞与レコードは月給外挿の基準にしない。

社会保険料見込み `S` は、実績の健康保険・厚生年金・雇用保険の合計に、最新月給の社会保険料を残月数だけ外挿した額を加える。未支給賞与分は、最新月給の額面に対する社会保険料比率を賞与見込みへ掛け、円未満を切り捨てる。

## 所得と上限額

給与所得控除、所得税と住民税の基礎控除、所得税の限界税率は令和7年分の定数を使う。課税所得は控除後の額を 1,000 円単位で切り捨て、0 未満にはしない。

- 給与所得 = `max(0, R - 給与所得控除(R))`
- 合計所得 `A` = 給与所得 + その他所得
- 所得税の課税所得 `T_i` = `max(0, floor((A - 所得税基礎控除 - S - その他控除) / 1000) * 1000)`
- 住民税の課税所得 `T_r` = `max(0, floor((A - 住民税基礎控除 - S - その他控除) / 1000) * 1000)`
- 住民税所得割額 `P` = `floor(T_r * 0.10)`
- 上限額目安 = `floor(P * 0.2 / (0.9 - 所得税限界税率 * 1.021)) + 2000`

寄付合計が 2,000 円を超えるとき、所得税分、住民税基本分、住民税特例分を計算する。特例分は `P * 0.2` を上限とし、実質自己負担は寄付合計から三つの控除額を引いた額とする。

## 対象外と注意事項

次の要素は意図的に計算しない。

- 住民税の調整控除・均等割
- 寄付金控除の総所得に対する 40% / 30% 上限
- ワンストップ特例と確定申告の差
- 配偶者控除、扶養控除、医療費控除などの個別計算

画面には、令和7年分の税制に基づく概算であり、正確な上限額は自治体・税務署等で確認する必要がある旨を常に表示する。

## 税制定数の保守

税制値は `packages/backend/src/services/tax-parameters.ts` に一組だけ定義する。年度別テーブルや暗黙の切り替えは持たない。税制改正時はこのファイルと対応する境界テスト、概算である旨の表示を同時に見直す。
