# 概要

サブスクを登録できるのに、残高予測には出てこない。
機能が途中で止まっているように見えるが、そうではない。

サブスクの大半はクレジットカードで払っている。
そのカード代は、想定額または確定した実績額として、既に予測に入っている。
ここでサブスクを予測イベントとして足すと、同じ支払いを二度数えることになる。

このアプリが管理したいのは、カード明細の中身ではなく、カード以外の口座残高がどう動くかである。
サブスクの一覧は、その口座残高の予測とは別の目的、つまり「毎月いくら固定費が出ていくのか」を把握するための台帳として置いている。

# カード払いでないサブスクを予測に入れたい場合

口座振替のサブスクは、現時点では予定収支として登録する。
サブスク台帳に登録しても予測には反映されない。

台帳と予定収支の両方に登録すると、台帳の月額合計と予測の両方に出る。
これは二重計上ではないが、同じ支払いが二か所に見える状態にはなる。

# 集計

台帳は月別の内訳と年間合計を出す。

- 月別：その月に発生する回を [スケジュール](./schedule-and-business-day.md) から展開し、日付順、同日は名前順（日本語ロケール）で並べる。
- 合計：各回の金額を JPY 換算して足す。外貨のサブスクは口座と同じ換算規則に従う。
- 年間：1 月から 12 月までの月別合計を足す。年をまたぐ按分はしない。

# 価格変更と履歴

サブスクの `amount` は初期金額として残す。価格が変わるときは同じサブスク ID に適用開始日と金額を追加する。適用開始日は日本時間の暦日で、その日を含む。各課金発生日には、その日以前で最も新しい履歴の金額を使い、該当する履歴がなければ初期金額を使う。契約の開始日・終了日と価格の適用開始日は別の情報である。

週次課金などで月の途中に価格が変わった場合、発生回ごとに金額を解決してから JPY 換算し、月合計と年間合計を求める。日割りや差額請求は生成しない。年払いは実際の発生日の価格を使う。価格履歴は金額だけを管理し、周期・課金日・通貨・プラン名は履歴化しない。通貨と換算レートはサブスク本体の値を使う。

通常の価格変更は履歴を追加する。初期金額や履歴の訂正・削除は、過去の台帳集計を変える可能性があるため別操作として扱う。履歴のない既存サブスクは従来の金額で集計し、別登録したサブスクを自動統合しない。価格履歴を追加しても残高予測へは直接加算しない。

一覧では、同じサブスクの価格を適用期間ごとに別行で表示する。初期金額の期間は契約開始日から最初の変更日の前日まで、変更後の期間は適用開始日から次の変更日の前日までとし、契約終了日を越えない。終了した価格期間は「終了済み」に移し、予約済みの期間は一覧に表示する。表示上の行が複数でも契約 ID と登録件数は一つのままである。

`paymentSource` は支払い元を書き留める自由記述で、集計にも予測にも影響しない。
