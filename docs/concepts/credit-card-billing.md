# 概要

来月のカード代はわからない。
わからないが、ゼロで置くわけにもいかない。
毎月おおよそ 12 万円使う人なら、確定するまでは 12 万円が落ちるものとして残高を見ておくほうが安全である。

カードには `assumptionAmount`（想定額）を登録する。
請求が確定したら、その月の実績額を `PUT /api/billings/:yearMonth` で登録する。
予測は月ごとに、実績があればそれを、なければ想定額を使う。

# 仮定値の適用請求月

カードごとに `assumptionStartMonth` と `assumptionEndMonth` を指定できる。
どちらも請求月（YYYY-MM）を表し、両端を含む。片側だけの指定もでき、`null` はその側に制限がないことを表す。
両方 `null` の既存カードは従来どおり全請求月に仮定値を使う。

期間判定には請求データと予測イベント ID の請求月を使う。
引き落とし日が営業日シフトで翌月に移っても、明示した `settlementDate` が別の月でも、判定月は変わらない。
期間外では仮定値と安全弁を使わず、登録済みの実績だけを採用する。実績がなければ 0 とし、予測イベントを作らない。実績 0 の登録と未登録は区別する。
期間を終えても過去・将来の登録済み請求や確定済み取引は削除しない。カードの削除や解約を意味する設定ではない。

たとえば旧カードの終了月を 10 月、新カードの開始月を 11 月にし、両方の仮定額を 12 万円にすると、実績のない各月には 12 万円だけを採用する。
旧カードに 11 月の実績 3 万円があれば、11 月は旧カード 3 万円と新カード 12 万円を採用する。
カードを併用できるため期間の重複は許し、一方を編集しても他方の期間や金額は変更しない。

# 安全弁

実績が入っていれば常に実績を使う、とはしていない。
翌月以降の月については、実績額が想定額を下回るときに想定額のほうを採用する。

| 月 | 実績 | 想定 | 採用 | 種別 |
|----|------|------|------|------|
| 当月（offset 0） | 80,000 | 120,000 | 80,000 | `actual` |
| 翌月以降（offset ≥ 1） | 80,000 | 120,000 | 120,000 | `safety-valve` |
| 任意 | なし | 120,000 | 120,000 | `assumption` |
| 任意 | 150,000 | 120,000 | 150,000 | `actual` |
| 適用期間外 | 30,000 | 対象外 | 30,000 | `actual` |
| 適用期間外 | なし | 対象外 | 0（イベントなし） | `none` |

翌月以降の請求額は、締め日を過ぎるまで増える余地がある。
締め前の途中経過を実績として扱うと、予測が実態より楽観に振れる。
当月ぶんは既に締まっており、その心配がないので実績をそのまま使う。

採用した額が 0 以下の月は、イベント自体を作らない。

# 引き落とし日

引き落とし日は次の順で決まる。

1. その月の請求データに `settlementDate` があれば、その日付をそのまま使う（営業日シフトは適用しない）。
2. なければ、カードの `settlementDay`、未設定なら既定の締め日から日付を組み立て、カードの `dateShiftPolicy` に従ってシフトする。

`settlementDate` をシフトの対象外にしているのは、明細に印字された日付を人が入力した値だからである。

# 予測イベントとの対応

生成されるイベントは種別 `expense`、生成元 `credit-card`、ID は `credit-card:<カード id>:<YYYY-MM>` である。
実績を使った月の説明文は「カード名 引き落とし (2026-08)」、想定額と安全弁の月は「カード名 仮定値 (2026-08)」になり、`isAssumption` が `true` になる。

引き落とし先の口座はカードに紐づく `accountId` である。
未設定のカードは合計残高だけを動かし、口座別の予測には現れない。
